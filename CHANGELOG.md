## [Unreleased]

### Added

- Code blocks with the language `svg-studio` are shown as an image (the SVG is checked by the sanitizer first; a rejected SVG shows the reasons and buttons to repair or edit it instead of a picture). The image never runs scripts and its styles cannot reach Obsidian.
- A button "Edit in SVG Studio" on code blocks and on embedded `.svg` files (also in pop-out windows), and a context-menu entry "Edit SVG" on `.svg` files.
- Commands "New SVG" and "Edit SVG" (German: "Neues SVG", "SVG bearbeiten"); "Edit SVG" works on the active `.svg` file, in a `svg-studio` block at the cursor, or on an embedded `.svg` at the cursor.
- Settings: help row first, then "Apply new SVG as" (file in the attachment folder, code block at the cursor, ask every time). The panel itself is a shell for now.
- Panel (first part): a sidebar view with the target line, the model row (model, reload, thinking level, "other endpoint"), the quality line, the prompt field (Cmd/Ctrl+Enter sends), a streaming answer area with status and Stop, the list of rounds and Apply/Discard buttons. An invalid answer goes back to the model up to twice ("Attempt 2 of 3: answer invalid …"); an answer that is invalid and was cut off at the limit is not asked again ("Too big for one round with this model"). Changing an image whose elements have no `id` asks nothing and says so. The settings get the section "Language model" (endpoints, model, request). Sampling is the one that was measured: temperature 0.2, thinking off, 16384 tokens.

- Apply: a new SVG becomes a file in the attachment folder (name from the first line of your prompt, never overwrites, numbered when taken) with `![[name.svg]]` at the cursor of the note you used last, or a `svg-studio` code block at the cursor, or you are asked each time. Without an open note only the file is created (a code block is greyed out with the reason). If that note is in reading view, the block or link is added at the end of the note and the message says so. An existing code block is rewritten only if it is still the one the panel opened ("Block changed" otherwise); an existing file gets a backup copy first (plugin folder `snapshots/`) and keeps your hand edits made since. The finished text is checked by the sanitizer before anything is written; if it fails, nothing is written. A round that replaces the whole image, or "Assign names" followed by further rounds, stops when the file was changed by hand since the round (nothing is lost silently). Applying twice in a row or during a run writes once or not at all.
- Opening an existing SVG shows what is wrong with it: unreadable or rejected by the sanitizer (button "Repair", asks the model, you check the result as a round), elements without a name (button "Assign names", no model) and editor data from Inkscape (button "Remove editor data", no model, the result is shown as a list of changes).

- Review list: every change of a round is a card ("Circle mond: r 40 → 60", "Shape changed", "Rectangle door: added", "Moved to the front"), accepted by default and rejectable one by one, with "Reject all", a jump to the element in the preview, a word diff for changed values, and one card "Whole image replaced" with before/after previews when a round cannot be split. Rejections go into the next request ("Feedback on the last round"). Cards of a round that a later round builds on are locked. A card can carry a comment: "Comment" opens a multi-line dialog, the comment stays on the card (an accepted change stays accepted) and goes into the next request together with the rejections. A round that replaces the whole image has no comment button.
- Number fields: click an element in the preview and edit its values (circle cx, cy, r; ellipse; rect x, y, width, height, rx; line; text position, size and text; fill, stroke, stroke-width; move and rotate for paths, polygons, polylines and groups; the rotation turns around the middle of the element as the browser measures it). Entering a value (Enter or leaving the field) changes exactly one attribute; consecutive edits gather in one round "By hand: mond r 60, door x 80" that you can step back from like any other round. Values with units or percent, and elements with a transform the fields cannot show (matrix, skew, scale), are read-only with the reason.
- Opening an existing SVG shows its preview, the background controls, the measure line and the number fields right away, before any round has run: pick an element, change a number, and the first edit becomes the first round ("By hand: …"). A SVG that is unreadable or rejected by the sanitizer keeps showing the repair card instead of a preview; a new SVG keeps the empty state.
- Safety net against drawings that freeze Obsidian: before an SVG is drawn (code block in a note, panel preview, before/after cells) a mark is written to a device-local IndexedDB database (committed to disk immediately, so it survives a hard quit; it is not synced; `localStorage` would not, Chromium delays it by up to a minute). A watchdog timer then measures how late its ticks arrive: the mark is removed after about two seconds of a responsive main thread, not when the image fires "load". A gap of one second or more (between 1.0 and 1.25 seconds depending on when it starts relative to the timer), or sustained load (more than about a third of the time late: frames of 350 milliseconds or longer in Chromium), turns the mark into a lasting one, also when you switch notes while the window is frozen. If Obsidian froze and was quit while the mark stood, or the mark is lasting, the block shows "This image blocked the display last time." with a button "Show anyway" instead of drawing it again; a mark never blocks for longer than a week. Measured in an Obsidian test instance: quitting in an orderly way (signal or browser close) while the watchdog still observes leaves no mark behind; a note whose block froze the window (heavy style rules, accepted by the sanitizer) leaves a mark written 40 ms after the note was opened, which survives `kill -9` 0.3 and 1.5 seconds later; the restarted instance shows the placeholder instead of freezing again, and without the mark the same note freezes it. Measured in Chromium: masks, dashed strokes, filters and heavy style rules are caught from about one second; sustained load with frames of 350, 500 and 700 milliseconds was caught in 9 of 9 runs, while single spikes of 0.85 seconds, two spikes of 0.6 seconds and ordinary load of 20 to 150 milliseconds per tick left the mark to be removed after about two to four seconds; 38 real SVG files drawn one at a time never became lasting. Known limits: freezes shorter than about one second; a freeze that starts after the watch window (a CSS animation with a long delay); an image below the visible area that is only drawn when you scroll to it; several blocks drawn at once share every gap, so one expensive block can make harmless blocks next to it lasting too (one click on "Show anyway"); redrawing an image that is already shown. New setting "Show SVG in notes automatically" (on by default): switch it off and every block shows a button instead of the image. If IndexedDB is unavailable the marks live in memory only. SVGs embedded with `![[name.svg]]` are drawn by Obsidian itself and are not covered.
- Pure core: element diff with a completeness check (the answer of the model is split into entries you accept or reject one by one), canonical form, the prompts of the measurement, answer reader and validators (`protocol.ts`).
- Pure core: round model for the panel (rounds with accept/reject per entry, hand edits, rule rounds for ids and editor metadata, apply against the text that stands now) and removal of editor metadata (Inkscape `sodipodi:`/`inkscape:`) as a visible rule round.
- Pure core: quality line from the measurement of 2026-11-02 (what was measured per model and task, tied to the measured prompt); not shown yet.
- Pure core: element scanner with UTF-16 source offsets and stable element keys, byte-preserving change lists (`change`, `add`, `remove`, `move`) with an all-or-nothing round-trip guard, id assignment and `data-unit`, canvas measurement from `viewBox` or `width`/`height`.
- SVG sanitizer `svg-guard` vendored from code-kit (rejects instead of stripping).
- Measurement lab for local models (`npm run lab`) with recorded answers from two models.

### Changed

- Internal: obsidian-kit 0.80.1 (was 0.80.0): a block that moved while a round was open (you typed a line above it) is found again when exactly one block matches, so Apply still writes to it and the rounds are kept; with two identical blocks it still says "Block moved".
- Fixed: the review list paired `<style>` elements by position, so accepting only some of the changes could lose a style that both texts contain or duplicate it; styles are now paired by content.
- Fixed: a large replaced or wrapped element showed no detail on its card, so a colour changed on the side stayed invisible; the card now shows the differences, shortened with "…".
- Fixed: the "Edit in SVG Studio" button on an embedded file resolved the link against the active note instead of the note that holds the embed, and kept the file it found when the embed was decorated; it now resolves on click. The note that Apply writes to is the one you used last, also in a pop-out window.
- Fixed: a SVG could lift the height limit of the preview with a style rule of its own; the limit now sits on the wrapper around the preview. A SVG over the size limit no longer offers "Repair" (it would have sent the whole text to the model).
- Fixed: on the review cards the struck and the inserted value stood next to each other without a separator ("x 165145"); they now read "x 165 → 145".
- Internal: obsidian-kit 0.80.0 (was 0.79.2) with the text-input dialog `promptText` (`prompt-text`, now vendored with its CSS) for the comment button; the rest of the kit release is the same code with a new header line.
- Internal: the language-model connection and the panel modules (`llm-connection`, `model-bar`, `thinking-control`, `stream-area`, `version-list`, `request-section`, `chat-host` and their dependencies) from obsidian-kit 0.79.1, the matching code-kit modules (endpoint, sampling profiles, SSE, redaction, …) from code-kit 0.55.0. The base pin of code-kit stays 0.52.1.
- Internal: vendored code-kit 0.52.1 and obsidian-kit 0.78.0 (retry on an invalid answer, status indicator, choice dialog, block writer, unwrapping of model answers, measured-quality (0.55.0), fences, panel-session, rounds and run-slot (0.54.0) from code-kit); `svg-guard` and `safe-markdown` are byte-identical to the 0.45.0 snapshot apart from the header line. No visible effect: the plugin has no user interface yet and carried none of the building blocks. Skipped kit releases read: code-kit 0.46.0 to 0.52.1 (audio, recording, diarization, MIDI/DAWproject, loopback and asset helpers, test timing, `answer-retry`) and obsidian-kit 0.76.0 to 0.78.0 (chat window and model bar on phones, host spacing, chat leaf placement, `canonVaultDir`) — none touches a module this plugin vendors, and the audio and Python releases do not concern it at all.
- Internal: vendored obsidian-kit 0.79.1 (was 0.78.0) with help row, settings walker, confirm dialog, segmented control, accept-into-note, review list, redline, file snapshot (grandfather-father-son rotation), fence scan. The skipped kit releases 0.76.0 to 0.79.1 read: choice dialog and status indicator (0.76.0), chat window and model bar on phones (0.76.0, 0.76.1, 0.77.1), chat leaf placement (0.77.0), `canonVaultDir` (0.78.0), accept-into-note, file snapshot, fence scan and the decision state of the review list (0.79.0), snapshot rotation by grandfather-father-son (0.79.1). The plugin carried none of the chat window and model-bar modules, so nothing changes for you; the new modules are used from the next steps on.
- Fixed: a new SVG (embed or code block) inserted at the cursor of a note with properties (front matter) now lands behind the properties instead of in front of them or inside them (obsidian-kit 0.79.2; Obsidian opens such a note with the cursor on the first line behind the properties, so this only hit a cursor moved into the properties by hand). Internal: obsidian-kit pin 0.79.2 (was 0.79.1); the kit release changes `insertAtCursor` only, plus the `getFrontMatterInfo` test double.
